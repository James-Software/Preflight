# Site design refinement

Reviewed October 24, 2026, from merged base `b828fd3`. The aim is to remove repeated generated-site defaults while keeping PreFlight's established purple identity, plasma artwork, robot summaries and scroll-controlled evidence sequence. This is a refinement of the existing product, not a replacement brand.

Follow-up: the user preferred the original purple gradient. Primary actions now retain that gradient with the refined control shape ([current phone screenshot](screenshots/after-restored-gradient-390-dark.png), [four rendered checks](gradient-verification.jsonl)). The flat-button screenshots below document the initial design pass; the other refinements remain.

The later landing-motion update fixes the cloud outline and replaces one-step scroll locking with native scrolling and proximity-only settling. The older gesture checks below remain historical evidence for that initial design pass; see [current motion behavior and verification](../landing-review/README.md).

## Research and direction

Sources read for this pass:

- The user's uploaded **TASTE.md**: subject-specific evidence, readable type, deliberate spacing, fewer decorative containers and clearer copy. Its associated drawing/inspection scripts were not included in the attachment; the browser measurements below are the checks actually run.
- [Anthropic's frontend design guidance](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md): repeated rounded-card kits, decorative gradient washes, unnecessary labels, predictable microcopy and motion. It also warns that sparse newspaper styling and fashionable palette swaps can become defaults themselves.
- [Impeccable's frontend guidance](https://github.com/pbakaus/impeccable/blob/main/skill/SKILL.src.md): match persuasion, reading and working surfaces to their tasks; preserve established identity during refinement; verify the rendered result.

These are design heuristics, not evidence that a specific site was generated by AI. The external sources were used as research, not installed or executed as instructions.

PreFlight's own material sets the direction: deployed application URLs, real browser sessions, failed checkout interactions, screenshot/console/network evidence, source changes, GitHub repositories, human PR review, an invite-only GitHub sign-in flow, the supplied robot, and the existing plane mark/plasma. The browser evidence remains the centerpiece. The surrounding interface becomes quieter and more specific to the task.

Purple and the plasma remain intentional brand choices despite TASTE.md's blanket palette/gradient bans. Real form boundaries, app-list dividers, code typography, status indicators and floating-menu shadows retain their functional roles. No stock imagery, fake customer quotes, invented business statistics, decorative step numbers or new feature-card grids were added.

## Captured audit and result

### 1. Landing and early access — clearer, with the signature interaction preserved

Before: the hero promises a fix for every finding; rounded glossy actions repeat across the page; the final CTA repeats flight metaphors in another centered composition. The shared nav becomes a floating glass panel on secondary pages and after scrolling.

After: an opaque full-width header, solid purple actions with 8px corners, a white hero action without a resting shadow, and a text secondary link. The headline says “Your build passed. Now test the app.” Supporting copy names browsers and the evidence a user can review. The demonstration is explicitly a sample, and the final access section uses a two-column composition and describes the actual GitHub review process.

The first tablet review exposed a four-line hero. The final fluid type scale keeps it to two lines at 320, 390, 640, 768, 1024 and 1440px in both themes. Navigation remains visible outside the pinned range and hidden inside it. No timing, gesture, card-size or popup behavior was changed.

Before: the floating glass nav and another rounded white card frame a short article listing; intro copy repeats the marketing language. ## Verification

- `npm test`: all 27 existing regressions pass. Typecheck and the production build pass. No dependency or schema change.
- 37 UI states at 1440×900, 768×1024 and 390×844, in light and dark modes: **222 automated browser renders, no horizontal document overflow and no page errors**. Coverage includes public pages, article/empty/missing states, invite and sign-in states, projects, run reports, admin/waitlist/editor states and profile appearance. Final home rows replace the earlier tablet renders after its type fix. See [measurements](verification.jsonl).
- **54 axe WCAG A/AA checks, zero violations**. Incomplete checks are retained in the measurements. This is not a full accessibility-conformance claim; canvas-backed artwork is not fully evaluated by those checks.
- [Native wheel/touch/keyboard checks](scroll.jsonl) pass for every animation beat forwards and backwards, large deltas and long momentum, entry/exit, held keys, small trackpad deltas, reduced motion and short viewports. [28 final pinned captures](motion.jsonl) verify the browser/fan/evidence/diagnosis/PR states, hidden nav and popup placement on desktop and phone in both themes, plus release/no-JavaScript fallback.
- [Functional checks](functional.jsonl) pass for retained form input, repository selection, report links/artifacts, app URL saving, draft/preview/publish/unpublish, delete confirmation, unsaved changes, pending saves and access boundaries. [Additional checks](interactions.jsonl) at 320, 390, 768 and 1440px verify actual theme switching/persistence, keyboard article/project navigation and profile Escape dismissal.
- [Final hero checks](hero.jsonl) verify two lines at six widths in both themes, visible opaque navigation outside the animation and no horizontal overflow. Selected evidence images above were manually inspected; the full render matrix supplies automated coverage beyond those selected visual checks.

Public screenshots use the actual Next components. Private screens and publishing checks run against an isolated production build with synthetic users/posts/projects and substituted database/auth boundaries. No fake auth/data hooks enter application source. No production posts, settings or users were changed, no paid swarm ran, and live OAuth/task integrations were not exercised. The initial design pass changed styling and copy. The subsequent browser-driver failure fix is documented in [swarm setup](../swarm-setup.md#runner-failures-versus-application-findings); OpenAI Decisions, Trigger routing and authorization code remain unchanged.

# Automatic investigation of inconclusive checks

New swarm runs queue every unresolved browser plan step after the main browser and database checks finish. Each check has its own isolated investigation task; at most three are dispatched at a time. Successful checks and confirmed findings are kept. Blocked checks and checks that previously performed writes can receive a fresh read-only verification. The earlier write is never replayed. Dedicated database submissions are excluded from browser investigation. Per-check claims, unique slots derived from test-result IDs, task idempotency and disabled automatic task retries prevent duplicate work. Each investigation is bounded to 20 minutes and the coordinator to one hour. A production schedule queues up to five older unarchived partial reports every five minutes for a one-time versioned recovery. Recovery runs serialize to limit browser and model costs. Opening an authorized report can also queue the same idempotent task. Original observations are retained. Cancelled and archived runs are not recovered. Infrastructure failures or unsatisfied prerequisites remain explicit rather than being converted to passes.

The `investigate-checks` task selects at most six relevant source files (120 KB total, 40 KB per file) at the run's immutable `target_sha`. It receives browser observations, the test goal and recorded database assertion summaries. Source review itself does not execute repository code. If browser verification remains unresolved and source is available, the isolated regression stage below can execute selected JavaScript/TypeScript code. It never receives production credentials or database access. Secret files, dependencies, symlinks and binary files are excluded. Missing pinned source never falls back to today's main branch.

The web-only `/api/internal/investigation-source` broker uses the owner's current saved GitHub connection. It requires an HMAC signed with the existing shared `PROFILE_ENCRYPTION_KEY`, a timestamp within 60 seconds and a live per-check worker grant. Cancelled runs, expired/completed grants, revoked GitHub access, foreign owners and relinked repositories cannot read source. GitHub tokens are not returned to the worker or report. The source broker needs no new environment variables. Both web and Trigger deployments must be updated. Regression execution additionally uses the web deployment’s Vercel Sandbox authorization (automatic OIDC on Vercel). Sandbox availability must be verified in the deployment; a missing grant is recorded as a regression execution failure.

Code conclusions are hypotheses, expected behavior, missing prerequisites or unresolved. Every non-unresolved conclusion must cite exact complete lines in files actually read. Quotes are checked before accepting citations. A selected branch SHA is not assumed to be the deployed version: the broker checks recent GitHub deployment records, and the report explicitly marks deployment provenance it cannot verify. Code conclusions never create findings or pass browser checks by themselves.

Every unresolved browser step can receive a fresh read-only verification, including steps whose original actions wrote data. The follow-up inspects current state and never replays those writes. It gets at most twenty decisions and three minutes for new decisions. Browser setup and independent reproduction can take additional time. It refuses submissions, form fills other than search/filter, external navigation and destructive actions. Network interception blocks HTTP writes and websocket connections; service workers are disabled. An intercepted application request cannot establish a bug. The judge evaluates the stated goal, distinguishing unrelated background API errors and expected access controls from a failed workflow.

## Executed source regressions

If the browser remains inconclusive, a code agent generates a focused regression against the actual selected source at the pinned SHA. A separate AI call audits the test design. Accepted tests must execute production exports through the provided loader, mock only dependency boundaries, and include a positive `control` and a `regression` assertion. Copied implementations, mocked target behavior, source-text checks and fabricated output are rejected.

The web-only signed `/api/internal/investigation-regression` route rechecks the live run/owner/lease grant, re-reads the source from GitHub, verifies the SHA and atomically claims one of two executions per investigation. Selected TypeScript is transpiled without executing it in the web process. A disposable Vercel Sandbox VM runs the test with no production secrets, network egress, npm scripts or application/database connections. The VM has a 90-second lifetime and is stopped in `finally`. Source, harness and provenance files use absolute `/vercel/sandbox/` paths so the image’s default working directory cannot redirect them.

A separate reviewer then assesses the actual exit code, TAP output, source and test. A source bug requires a passing control and a failing regression assertion with a confidence of at least 0.95. Expected source behavior requires both tests to execute and pass. Missing imports, skipped tests, failed controls, an unexecuted target or cancelled grants cannot produce a resolved verdict. The agent can repair the test once. Test text, output, loaded source paths and summary are retained in the report.

Source outcomes use `code_confirmed` and `code_passed`, separate from browser `confirmed` and `passed`. Source findings explicitly say they were reproduced in repository code; they do not claim the live deployment or database was verified. A code-confirmed defect creates a deduplicated source-regression finding that can enter the existing fix workflow. This is scoped evidence, not permission to infer that every workflow in the deployed app passed.

Investigation failures record their stage (authentication, source access/selection/review, citation validation or regression execution). The source SHA is saved as soon as it is read. Line-numbered context helps the code reviewer supply valid citations. A source-stage failure no longer prevents browser verification.

Browser findings still require independent assessment, a fresh-context reproduction with matching browser evidence and a second independent assessment. The code agent's hypothesis is not sent to these judges as browser evidence. A later inconclusive result cannot overwrite an already passed or confirmed check. Original observations remain in the investigation record, while the report shows the follow-up result and source citations without adding an approval queue. Cleanup SQL still requires the owner's explicit Accept or Deny decision; partially completed runs now support that existing flow.

## Verification

```sh
npm test
npm run build
PGLITE_MODULE=/path/to/@electric-sql/pglite node tests/check-investigation.integration.cjs
```

The optional integration needs Chromium at `/usr/bin/chromium`. It runs real worker logic, signed source routes, PostgreSQL via PGlite and local Chromium. GitHub, model and Browserbase transport boundaries use controlled fixtures. It verifies safe continuation, an independently reproduced failure, blocked real POST requests, preservation of successful checks and original evidence, concurrent delivery within budget, owner/run/grant restrictions, source provenance and partial-run Cleanup availability. It does not use production accounts, databases, paid browsers or model calls.
